# 4.5: Build a Path with the Pedro Visualizer

Use the [Pedro Pathing Visualizer](https://visualizer.pedropathing.com/) to design
a second path, export its Java code, and add it to the Autonomous OpMode from
Lesson 4.4.

## Learn the Visualizer with one line

Start with a single line so you can learn the tool before designing the complete
path.

1. Set the **Starting Point** to match the simple path from Lesson 4.4.
2. Create one line to an endpoint.
3. Select **Constant** heading.
4. Use **Play/Pause** to preview it.
5. Move the endpoint and observe how the preview changes.

- A path with no control points is a `BezierLine`.
- Adding control points creates a `BezierCurve`.
- Heading is configured separately for each path.
- The preview shows the intended path; it does not prove the physical robot can
  follow it.

## Design the second path

Create one Path Chain named `VisualizerPath`.

Your path must have:

- at least three path segments;
- at least one straight line;
- at least one curve;
- at least one heading change;
- a route meaningfully different from Lesson 4.4; and
- enough clearance for the entire robot, not only its center point.

Use **Add Path** to create segments and **Control Points > Add** to create curves.
Choose Constant or Linear heading for each segment and use Play/Pause to inspect
the complete motion.

Keep this lesson to one Path Chain. Do not add waits, callbacks, or multiple
chains yet.

## Preview and save

- [ ] The Starting Point is correct.
- [ ] Every segment is assigned to `VisualizerPath`.
- [ ] Segments appear in the correct order.
- [ ] Heading changes look correct.
- [ ] The robot remains inside the intended test area.
- [ ] The preview runs continuously from start to finish.

Use **Save As** to save the `.pp` project file in the Season Repository. This lets
you reopen and modify the path later.

## Create a second Autonomous OpMode

Copy `FirstPedroAuto.java` from Lesson 4.4 to a new file named
`VisualizerAuto.java`. Rename the class and annotation:

```java
@Autonomous(name = "Visualizer Auto", group = "Learning")
public class VisualizerAuto extends LinearOpMode {
```

Remove the old `path` field and `buildPath()` method. Keep the follower, starting
pose, and OpMode lifecycle.

## Export the path

In the Visualizer:

1. Select **Export Path**.
2. Select **Java Code**.
3. Select **Class Only**.
4. Copy the generated `Paths` class.
5. Paste it inside `VisualizerAuto`, before the class's final closing brace.

Do not use **Full Code**. It generates another OpMode and additional framework
code that you do not need.

## Connect the generated path

Add the generated paths field:

```java
private Paths paths;
```

Update `runOpMode()` to build and follow the exported Path Chain:

```java
@Override
public void runOpMode() {
    follower = Constants.createFollower(hardwareMap);

    // Builds the PathChains exported from the Visualizer.
    paths = new Paths(follower);

    // Must match the Visualizer Starting Point and physical placement.
    follower.setStartingPose(startPose);

    telemetry.addLine("Ready");
    telemetry.update();

    waitForStart();

    if (isStopRequested()) {
        return;
    }

    // Use the exact PathChain name generated by the Visualizer.
    follower.followPath(paths.VisualizerPath);

    while (opModeIsActive() && follower.isBusy()) {
        follower.update();

        telemetry.addData("x", follower.getPose().getX());
        telemetry.addData("y", follower.getPose().getY());
        telemetry.addData("heading", follower.getPose().getHeading());
        telemetry.update();
    }
}
```

Use Android Studio to add the required imports. Confirm that the generated field
name matches `VisualizerPath` exactly, including capitalization.

## Test the exported path

- [ ] `Visualizer Auto` appears on the Driver Station.
- [ ] The physical starting position matches the Visualizer Starting Point.
- [ ] The robot follows the same general geometry shown in the preview.
- [ ] Heading changes occur on the expected segments.
- [ ] The robot maintains safe clearance.
- [ ] The path works repeatedly.
- [ ] Driver Station Stop works during the path.

## Troubleshooting

| Symptom | First things to check |
|---|---|
| Generated code does not compile | Use Class Only instead of Full Code, then resolve the generated imports |
| Generated Path Chain is missing | Confirm every path is assigned to the intended chain before exporting |
| Chain name is not recognized | Use the exact generated Java name, including capitalization |
| Robot follows the old path | Confirm `followPath()` references the generated chain |
| Entire path is shifted | Visualizer Starting Point, `setStartingPose()`, and physical placement do not match |
| Path is mirrored or rotated | Check the Visualizer field orientation and Pedro coordinate system |
| Heading is wrong | Check each segment's heading mode and start/end heading |
| Curve differs from the preview | Check localization, tuning, wheel slip, and control-point placement |
| Robot stops between segments | Confirm the segments belong to one Path Chain and are ordered correctly |
| Changes are missing on the robot | Save, export again, and replace the older generated `Paths` class |
| Path project is lost | Save and commit the `.pp` file instead of relying on the browser session |
| Preview clears an obstacle but the robot does not | Verify robot dimensions and leave additional physical clearance |
