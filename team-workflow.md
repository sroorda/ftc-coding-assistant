# Team Workflow Bootcamp

You now know enough Java to begin working in a shared repository. In this workshop,
you will move one small change from your computer through review without risking
someone else's work.

Complete the [Level 1 readiness check](levels/01-java-foundations.md#level-1-readiness-check)
before you begin. Use this training repository or another practice repository—not
active competition code.

## Your mission

By the end, you will be able to create a branch, inspect your change, commit it,
open a pull request, and respond to review. You are learning a safe workflow, not a
list of commands to memorize.

## Move one change through the workflow

Choose a tiny documentation change or a completed Level 1 improvement.

1. Clone the practice repository and find the default branch.
2. Create a short-lived branch named for the change.
3. Make one small change.
4. Inspect `git status` and `git diff` before staging anything.
5. Commit with a message that describes the outcome.
6. Push your branch and open a pull request.
7. Explain your diff to a peer or adult reviewer.
8. Respond to one review comment and update the branch if needed.
9. Merge only after adult approval, then update your local default branch.

## Check your work

You are finished when:

- your pull request has one clear purpose;
- you can explain every changed line;
- generated files, credentials, and unrelated changes are absent;
- you recorded the verification command and result;
- you can distinguish a required correction from an optional suggestion; and
- you know when to stop and ask for recovery help.

Do not experiment with destructive Git commands to escape a confusing situation.
Preserving everyone’s work matters more than appearing to fix it alone.

## How collaboration will grow

| Level | Your next teamwork challenge |
|---|---|
| 2 — Hardware Lab | keep cumulative work on a personal branch and use selected lesson pull requests for peer review |
| 3 — Robot Systems | integrate your subsystem with a partner's subsystem |
| 4 — Autonomous Motion | review paths, poses, constants, and tuning evidence |
| 5 — Coordinated Autonomous | coordinate changes across pathing and mechanism code |

You do not need a permanent lead title. As your skills grow, you can temporarily
own a subsystem, test, or pull request and teach the next person what you learned.

Before Level 2, read [Your Level 2 Git Workflow](docs/level-2-git-workflow.md) to
see how personal branches and temporary review branches work together.

## Use AI safely

Ask AI to explain a command, help you read a diff, or suggest review questions. Do
not ask it to push, merge, change permissions, conceal an error, or approve its own
work. A human author and human reviewer remain responsible.
